# gujiga — 제안은 AI가, 실행은 사람이 하는 주식투자 앱

**한 줄 요약: AI는 주문 제안서("출사표")까지만 만들고, 실제 돈이 나가는 주문은 사람이 실행 버튼을 눌러야만 나갑니다.**

한국투자증권(KIS) API로 실전·모의 매매를 돌리는 개인 프로젝트입니다. AI가 실수하거나 폭주해도
피해가 제한되도록, "AI 단독으로는 어떤 경우에도 주문이 나가지 않는다"를 구조로 보장하는 것이
이 프로젝트의 핵심입니다.

## 안전장치 (겹겹이)

돈이 걸린 시스템이라 안전장치를 여러 겹 둡니다:

1. **출사표(주문 초안) 체계** — AI는 초안만 작성. 진입 가격대·손절선·목표가·기한·투입 금액
   5가지가 모두 있어야 성립하고, **사람의 확인 플래그 없이는 클라이언트가 주문 자체를 차단**합니다.
2. **1회 주문 한도** — 실전 1회 최대 20만원, 모의 50만원. 넘는 초안은 실행이 막힙니다.
3. **하루 손실 서킷브레이커** — 당일 손실 -5만원 도달 시 그날 실전 매수를 전부 차단합니다.
4. **화이트리스트 + 지정가 전용** — 실전 매수는 사전 허용 종목만, 지정가(가격을 정해 내는 주문)만.
   시장가 주문은 실전에서 금지 — 급등락 때 예상 밖 가격에 체결되는 사고를 막습니다.
5. **긴급 정지(STOP 파일)** — 파일 하나 만들면 실전·모의 모든 주문이 즉시 멈춥니다.

개인정보도 같은 원칙으로 다룹니다 — 외부로 나가는 텍스트에서 계좌번호 패턴을 제거하는 것을
**테스트로 검증**합니다(로컬 장부에는 원문 보존).

## 기술

- **Node.js 내장 모듈만** (외부 패키지 0개) — 공급망 위험과 유지보수 부담을 줄이기 위한 선택
- 저장소는 **파일(md·jsonl) + Git** — DB 없이 모든 기록이 커밋으로 남아 되짚을 수 있음
- 한국투자증권(KIS) Open API 클라이언트 직접 구현
- 자동 테스트 **322건** (`node --test`, 테스트 파일 30개) — 주문 차단·한도·서킷브레이커 등
  안전장치가 전부 테스트로 못박혀 있음
- API 키·계좌 정보는 `secrets/`로 분리(커밋 금지), 테스트는 전부 더미값 사용

## 개발 방식 — OCTET 거버넌스

이 프로젝트는 제가 만든 스펙 관리 도구 [OCTET(octet-cli)](https://www.npmjs.com/package/octet-cli)으로
개발합니다. 매매 앱과 똑같은 철학입니다 — **초안은 AI가, 승인은 사람이.**

- 요구사항→설계→작업→테스트 문서 **253장**이 승인 게이트로 연결돼 `octet-docs` 브랜치에 있음
- 승인된 작업(TSK)을 구현한 커밋에는 id를 적어(`TSK-027: …`) `git log --grep`만으로
  "왜 이 코드가 생겼는지"를 문서까지 되짚을 수 있음
- AI(Claude Code)는 문서 초안·구현을 하되, 승인·실전 주문·키 접근은 금지

## 구조

```
src/      앱 본체 (주문 게이트키퍼 · 전략 · 현황판 등)
test/     자동 테스트 322건
bin/      운영 스크립트 (기동/정지/백업/검증)
config/   한도 · 휴장일 캘린더 등 설정 (키 없음)
clients/  증권사 API 클라이언트
refs/     운영 시나리오 명세
```

> 참고: "출사표·병력·현령" 같은 용어는 프로젝트 내부에서 쓰는 삼국지 비유입니다 —
> 주문 초안·투입 금액·권한 등급을 뜻합니다. 어려운 개념을 손에 잡히는 말로 바꿔 쓰는
> 습관의 산물입니다.
