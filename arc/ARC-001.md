## 시스템 모듈 구조

**한 줄 요약(확정): 회사 PC에서 도는 로컬 Node 데몬 1개 + 브라우저 UI(PC 전용) — 클라우드 서버는 두지 않고, 휴대폰은 알림만 받는다.**

| 비교 | A. 로컬 Node 데몬 + PWA (선택안) | B. 클라우드 서버 |
|---|---|---|
| 비용 | 0원 | 서버비 월 과금 |
| 키 보관 | 로컬에만(외부 전송 없음) | 서버에 키 업로드 필요 — RISK-001 악화 |
| 성향 적합 | zero-dependency·Git-native(OCTET과 동일 철학) | 운영 부담·의존성 증가 |
| 모바일 접근 | 같은 네트워크/터널 필요(약점) | 어디서나 접근(강점) |
| 장애 | PC 꺼지면 중단(약점) | 상시 가동(강점) |

선택 이유: 비용 0·키 로컬 유지·기존 자산(kis_client.js, jsonl) 재사용이 모두 A에 유리하다. 모바일 접근 약점은 알림 채널([[ARC-006]] 텔레그램 봇)로 보완한다 — 외부 접속은 지원하지 않기로 확정.

- 모듈: `daemon`(스케줄·정찰·판정) / `gate`(주문 게이트 — [[ARC-003]]) / `web`(로컬 HTTP + PWA UI) / `ledger`(파일 저장 — [[ARC-002]]).

## 데이터 흐름 (Data Flow)

브라우저(SCR 화면) → 로컬 HTTP(localhost) → 데몬 → gate → KIS API. 역방향: 데몬이 시세·체결을 파일 장부에 기록 → 화면은 장부를 읽어 그린다. 대시보드는 PC 전용이며, 휴대폰은 텔레그램 알림([[ARC-006]])만 받는다(확정).

## 인프라/의존성

- Node.js 단일 런타임, 외부 패키지 최소(zero-dependency 지향). DB 서버·클라우드 없음.
- 회사 PC 1대가 단일 실행 지점 — PC 꺼짐 = 루틴 중단(위험 참조).

## 보안 및 인증

- 로컬 HTTP는 localhost 전용(확정) — 외부 노출을 하지 않으므로 별도 원격 인증 계층을 두지 않는다.
- 증권사 키는 데몬 프로세스만 읽는다([[ARC-005]]).

## 위험

- 회사 PC 꺼짐·절전 → 정시 루틴 미실행(아침 브리핑·정찰 공백). 완화: 시작 시 자가 점검 + 미실행 감지 알림.
- 로컬 서버를 외부에 열 경우 인증 없는 노출 사고.

## 확정 (군주 결정 반영, 2026-11-24)

1. **모바일 외부 접속은 지원하지 않는다** — 대시보드는 PC 전용이고, 휴대폰은 알림([[ARC-006]] 텔레그램 봇)만 받는다.
