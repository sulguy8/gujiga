## 시스템 모듈 구조

**한 줄 요약(결정안): 데몬이 로컬 claude CLI를 `claude -p`(헤드리스, OCTET chat.js와 같은 방식)로 호출하는 `strategist` 모듈 — 도구는 읽기+초안 쓰기만, 호출 횟수는 상한제.**

| 비교 | A. 로컬 claude CLI 헤드리스 (선택안) | B. API 직접 호출 | C. LLM 없음(규칙만) |
|---|---|---|---|
| 비용 | 기존 구독 활용 | API 과금 별도 | 0 |
| 구현 | chat.js 방식 재사용 | SDK·키 관리 추가 | — |
| 해석 품질 | 충분 | 충분 | 없음(숫자만) |
| 로컬 철학 | 부합(ARC-001) | 외부 의존 | 부합 |

선택 이유: 이미 검증된 OCTET chat.js 호출 방식을 재사용하고 추가 과금·키 관리가 없다. C안은 degrade 모드로 항상 내장한다.

- 모듈: `strategist.call(기능, 입력)` 단일 진입 — 기능 4종: 군의 해석([[REQ-016]])·출사표 초안([[REQ-017]])·전략 건의([[REQ-018]])·통찰([[REQ-019]]).

## 데이터 흐름 (Data Flow)

규칙 엔진 판정(숫자) → strategist 입력(스냅샷·판정·관심 종목) → `claude -p` 1회 → 출력 파싱·검증 → 장부 기록/알림/초안 INSERT.

- **호출 상한**: 군의 1회 + 전황(15:05) 1회 + 척후는 규칙 엔진이 [액션 필요]로 판정한 회차만. 하루 최대 횟수는 설정값(guard_config 확장) — 초과 시 호출 생략+기록.
- **권한 모델**: strategist에 노출되는 도구 = 장부 읽기 + order_draft INSERT(ai·false 고정)뿐. kis-adapter·gate·confirm 함수는 프로세스 경계 밖(도구 목록에 없음) — [[REQ-002]]·[[REQ-017]] 불변식의 구조화.
- **인젝션 방지**: 뉴스·웹 텍스트는 "데이터" 블록으로 감싸 전달하고, 그 안의 지시문을 따르지 말라는 시스템 규칙 고정. 출력은 파서가 형식 검증(예상 밖 도구 요청·형식은 폐기).
- **degrade**: claude 실행 실패·부재 시 규칙 엔진 출력만으로 최소 보고 — 파이프라인은 멈추지 않는다.

## 인프라/의존성

- 로컬 claude CLI 설치 전제(없으면 degrade). 외부 패키지 추가 없음(child_process 호출).
- 출력은 구조화 형식(JSON 우선)으로 요구해 파싱 안정화.

## 보안 및 인증

- strategist 프로세스에 증권사 키·토큰을 전달하지 않는다(시세·장부는 데몬이 읽어 입력으로 제공).
- 웹 검색 결과 원문은 장부에 기록(판정 재현용), 프롬프트에는 데이터 블록으로만.

## 위험

- LLM 출력 형식 흔들림 → 파서 검증 실패 시 해당 기능만 생략(degrade), 재호출 남발 금지(상한 소모).
- 비용 폭주: 상한 로직 버그 시 과금 — [[TST-012]]에서 상한 강제 검증.
