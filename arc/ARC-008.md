## 시스템 모듈 구조

**한 줄 요약(결정안): 출처별 수집기 4개(KIS 일봉·네이버 장중 지수·웹 검색·KIS 투자자 동향)를 `market` 모듈로 묶고, 산출은 하루 1행의 시장 스냅샷([[DAT-013]])으로 통일한다.**

| 수집기 | 출처 | 담당 값 | 비고 |
|---|---|---|---|
| daily-kis | KIS 일봉(`FID_COND_MRKT_DIV_CODE=J`) | 종가·20일선·60일 일봉 | **판정용 유일 출처** |
| intraday-naver | 네이버 m.stock 지수 API | 장중 지수 | 참고·정찰용만 |
| overnight-web | 군사 엔진 웹 검색 1회 | 미국(S&P·나스닥·SOX·VIX)·야간선물 | 군의당 1회 |
| investor-kis | KIS 투자자 동향 TR | 코스피 외국인 순매수 | **TR id 미확정** — 장수 제안·군사 검토 |

금지 규칙: 네이버 일봉·basic은 NXT 포함이라 판정 경로 사용 금지(retro 교훈) — 기동 시 코드 검사로 강제.

## 데이터 흐름 (Data Flow)

08:30 전후: daily-kis·investor-kis(어댑터 경유, 1.2초 간격) + overnight-web(strategist 경유 1회) → 수집값+출처 태그 → 판정 엔진(날씨 [[REQ-020]]·신호등 [[REQ-021]], 순수 함수) → market_snapshot 1행 기록 → 군의([[REQ-016]])·촉군 출병 검사·현황판이 읽음. 장중: intraday-naver는 척후([[REQ-006]]) 참고값으로만.

## 인프라/의존성

- KIS 호출은 [[TSK-003]] 어댑터 경유(간격·토큰 공통). 웹 검색은 [[ARC-007]] strategist 경유(비용 상한 공유).
- 결측 시 대체 출처 금지 — 결측 표기 후 보수 판정(방어/꺼짐).

## 보안 및 인증

- 네이버·웹 검색 응답은 데이터로만 취급(인젝션 방지 규칙 공유). 수집기에 키 직접 노출 없음(어댑터 경유).

## 위험

- 외부 API(네이버) 형식 변경으로 수집 실패 → 결측 처리로 흡수되지만 장기화 시 판정이 계속 보수화. 완화: 수집 실패 연속 N일 경고.
- 기준 저점(SOX) 관리 누락 시 3번 신호등 오판 — 장부 '재진입 기록' 갱신 규칙 준수.
