## 시스템 모듈 구조

**한 줄 요약(확정, 군주 결정): gujiga Node 프로세스가 127.0.0.1 전용 '허도 관문'을 띄워 DPAPI로 키를 풀어 메모리에만 두고 KIS 호출을 대행한다 — Aside 루틴은 키를 영영 만지지 않는다.**

배경(왜 필요한가): [[ARC-005]] B안(DPAPI 암호화)을 적용하면, Aside 실행 환경(REPL)은 외부 프로세스를 못 부르고 Aside의 PowerShell은 보호 모드라 인터넷이 안 되므로 **Aside 루틴이 키를 풀 방법이 없다**. 관문이 이 간극을 메운다(RISK-001 대응의 완성). KIS 호출 규율은 [[ARC-003]]을 따른다.

## 데이터 흐름 (Data Flow)

Aside 루틴 → 얇은 kis_client.js → http://127.0.0.1:62910 (+토큰) → 관문: 토큰·Host 검사 → 안전장치 검사 → kis-adapter(1.2초 큐) → KIS → 응답 반환·order_log 기록.

- **실전 주문 2단계**: [[TSK-005]] 주문 게이트 완성 전까지는 현행 kis_client와 동일한 안전장치(confirmed 플래그 필수, guard 한도·화이트리스트·STOP·하루 손실)를 **관문이 직접 강제**. 게이트 완성 후에는 관문이 [[TSK-005]] 게이트를 경유시킨다(검사 로직 단일화).
- **관문 꺼짐**: Aside 루틴은 '[정지] 관문 꺼짐'을 보고하고 **주문하지 않는다**(조용한 실패 금지).

## 인프라/의존성

- Node 내장 http만(zero-dependency). 포트는 **62910 확정**(대시보드 62900·OCTET 62838과 비충돌) — 설정 파일로 변경 가능.
- 호출 간격 1.2초 큐·토큰 캐시(암호화)는 관문 안에서 일원화([[ARC-003]] 규율 승계).

## 보안 및 인증

- 바인딩: 127.0.0.1 전용(외부 인터페이스 금지) + **Host 헤더 검사**.
- **관문 토큰**: 기동 때마다 무작위 토큰을 새로 생성해 Aside 계정 폴더의 정해진 파일에만 기록(재기동 시 교체). 모든 요청에 토큰 필수 — 없거나 틀리면 401.
- 키·KIS 토큰은 DPAPI 복호화 후 메모리에만 — 디스크 평문 0, 응답·로그에 키·토큰 값 기록 금지.

## 위험

- 관문이 꺼져 있으면 Aside 루틴 전체가 정지 보고 상태(시세·잔고 포함) — 단일 장애점. 완화: 기동 확인을 아침 점검에 포함.
- 같은 PC의 다른 프로세스가 토큰 파일을 읽으면 호출 가능 — Aside 계정 폴더 권한에 의존(DPAPI와 동일한 신뢰 경계).
