## 상위 근거

**REQ-028 — 책사 7인 의견 생성** · [[REQ-032]](종합) · ARC-007(군사 엔진 호출 구조 — 호출 방식만 참고. frontmatter 정식 연결은 2026-11-26 군주가 제거: 참고 관계일 뿐 승인 게이트 의존을 두지 않기 위함)

## 시스템 모듈 구조

**한 줄 요약: 숫자 규칙 책사 3인은 로컬 계산(AI 0회), AI 책사 4인은 claude 1회 호출에 네 목소리로 묶되 별도 회차 없이 기존 호출(군의·척후)에 통합하고, 하루 전체 AI 상한은 8회 유지(2026-11-26 군주 확정) — 비용과 권한을 구조로 통제한다.**

- `council.js` (오케스트레이터): 안건 수신 → 규칙 3인 실행 → AI 1회 호출 → 형식 검증 → 장부 append → 제갈량 종합.
- 규칙 책사(로컬 함수, 결정적):
  - `advisor_곽가.js` — 차트·타이밍: 시장 스냅샷([[DAT-013]])의 가격·신호등 입력. 이동평균은 KIS 일봉 J 데이터에서 직접 산출한다(별도 지표 API 없음).
  - `advisor_법정.js` — 수급: **종목별 수급 TR(투자자별 매매 조회) 확정 전까지는** 시장 전체 외국인 순매수(src/market.js 기존 수집) + 보유 종목 일봉만으로 **제한 판정**한다(폴백 명시). 종목별 수급 TR 도입 시 판정을 확장한다.
  - `advisor_가후.js` — 리스크 반대 전담: 성벽(손절선) 거리·병력 한도·군령 위반 이력 체크리스트로 "하면 안 되는 이유"를 우선 탐색.
- AI 책사(묶음): 군사 엔진([[ARC-007]]) `claude -p` 1회 호출. 프롬프트에 노숙·순욱·육손·장송 4개 페르소나를 지정하고 **JSON 배열 1개**(4건: advisor·stance·confidence·rationale)로만 응답받아 파싱.
  - **호출 시점(2026-11-26 군주 확정)**: 별도 회차를 추가하지 않는다. 아침 안건은 **군의(08:31) 호출 1회에 합쳐서** 생성하고, 장중 안건은 **척후 몫 6회 안에서** 소화한다(척후 호출 하나가 책사단 목소리를 겸함).
- `scorer.js` (채점 배치, 하루 1회): 5거래일 경과 의견 채점 → score 이벤트 append → `rank.js` 재계산.
- `rank.js`: 장부에서 관직 재계산(멱등) → `ranks.json` 갱신.

## 데이터 흐름 (Data Flow)

안건 → [규칙 3인(로컬)] + [AI 1회(4목소리)] → 형식 검증(깨진 응답은 폴백) → `verdicts.jsonl` append(7건) → 제갈량 종합(가중 다수결, AI 0회) append(1건) → 의견판([[SCR-009]]) 표시 → (5거래일 후) scorer → score 이벤트 → rank 재계산 → 공적판([[SCR-010]]).

## 인프라/의존성

- Node 내장 모듈만(zero-dependency). AI는 로컬 claude CLI 헤드리스 — ARC-007과 동일 경로·동일 degrade(실패 시 폴백 의견, 처리 중단 없음).
- **비용 상한(2026-11-26 군주 확정)**: 하루 AI 총 상한 **8회 유지**(군의 1회 + 전황 1회 + 척후 [액션 필요] 최대 6회 — [[ARC-007]] 그대로). 책사단은 **별도 호출을 추가하지 않는다**: AI 책사 4인의 목소리는 군의(08:31) 호출 1회에 합쳐 생성하고, 장중 안건은 척후 몫 6회 안에서 소화한다. 상한 도달 시 AI 책사 4인은 폴백.
  - **ARC-007 개정 불필요(2026-11-26 군주 확정 — 통합 방식)**: 별도 회차가 없으므로 ARC-007 불변식 1(군의 1 + 전황 1 + 척후 6 = 하루 8회 확정)과 충돌하지 않는다.
  - 상한 경합 시 우선순위(확정): **군의·전황 > 책사단 > 척후** — 척후가 양보한다. (2026-11-26 군주 확정)
- 입력 데이터는 시장 데이터 수집 계층([[ARC-008]]) 재사용. 종목별 수급 TR을 추가하게 되면 ARC-008 개정 항목으로 다룬다. 장송의 DART 공시 파이프라인은 [[TSK-029]]에서 별도 설계.

## 보안 및 인증

- 권한: 책사단 모듈은 **읽기 + 장부 append만**. 주문 함수·실행 확인 플래그 접근 불가([[REQ-002]] 불변식, [[NTE-006]]과 동일).
- 인젝션 방지: 뉴스·공시 텍스트는 데이터로만 취급 — 본문 속 지시문을 명령으로 따르지 않는다.
- 키·토큰은 다루지 않는다(가격·수급 데이터는 관문 경유 조회).
