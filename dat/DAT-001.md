## 상위 근거

**REQ-001 — 출사표 필수 5항목 검증**

**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 출사표(주문 초안)는 5가지 항목이 모두 채워져야만 성립한다.**
출사표는 모든 주문의 출발점이다. 항목이 빠진 채 주문이 나가면 손절선 없는 매매 같은 사고로 이어지므로, 성립 요건을 시스템이 강제한다.
모든 출사표는 ① 진입 가격대 ② 손절선 ③ 목표가 ④ 기한 ⑤ 병력 수(투입 금액)의 5개 항목이 전부 채워져야 제출(저장)될 수 있다.
- 출사표 작성 기능(AI 생성 또는 수동 입력)이 존재한다.

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 출사표(주문 초안) 한 장 = 1행. AI가 만들고 사람이 '실행' 확인해야 주문이 되는, 모든 매매의 출발점 테이블.**

`order_draft` — 근거: [[REQ-001]](필수 5항목), [[REQ-002]](실행 확인 플래그), [[REQ-008]](손절선 종가 판정).

## 인덱스 및 제약조건

- PK: `id`. 인덱스: `(account_type, status)`, `(symbol, created_at)`.
- 값 제약: 필수 5항목(①~⑤)은 NOT NULL — 하나라도 없으면 INSERT 거부([[REQ-001]]). `troops ≥ 1` 정수. `entry_low ≤ entry_high`. 매수는 `stop_price < entry_low`, `target_price > entry_high`.
- `user_confirmed = false`인 실전(real) 출사표는 전송 불가([[REQ-002]]) — 전송 계층에서 강제.
- `created_by = 'ai'`인 행은 `user_confirmed`가 true로 INSERT될 수 없다(사람의 확인 행위로만 갱신).

```json
}
```
(병력 15명 = 15만원 — 현령 한도 20만원 이내)
