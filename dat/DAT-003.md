## 상위 근거

**REQ-003 — 주문 한도 검사: 1회 한도(관직 연동)·하루 손실 -5만원 차단**

**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 1회 주문 금액과 하루 손실이 정해진 숫자를 넘으면 주문이 차단된다.**
사람이 실수로 '실행'을 눌러도 피해가 한도 안에 머물도록, 금액 한도를 시스템이 강제한다.
주문 금액이 1회 한도(실전 20만원 — 관직 연동, 모의 50만원)를 초과하거나, 실전 총평가가 당일 시작 대비 -5만원 이하인 상태의 실전 매수는 차단된다.
- 현재 관직([[REQ-013]])과 당일 시작 시점의 실전 총평가 금액이 기록되어 있다.

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 모든 안전장치의 숫자(한도·기준)를 한 곳에 모은 설정 테이블 — 1행만 존재한다.**

`guard_config` — 근거: [[REQ-003]](한도), [[REQ-004]](화이트리스트·STOP). 숫자를 코드에 흩어두지 않고 설정 한 곳에서 관리하라는 REQ-003 동작 규칙의 구현체.

## 필드 정의 및 타입

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string | ✔ | PK, 고정값 `"default"`(1행 테이블) |
| per_order_limit_real | int(원) | ✔ | 실전 1회 한도. 기본 200000 — 관직([[DAT-011]])과 동기화 |
| per_order_limit_paper | int(원) | ✔ | 모의 1회 한도. 기본 500000 |
| daily_loss_limit | int(원) | ✔ | 하루 손실 한도. 기본 -50000(음수) |
| stop_file_path | string | ✔ | STOP 파일 경로(파일 존재 = 전체 주문 중단) |
| cash_ratio_min | decimal | ✔ | 군량(현금) 최소 비중. 기본 0.30 |
| correlation_max | decimal | ✔ | 상관계수 상한. 기본 0.70 |
| sample_min | int | ✔ | 가설 표본 최소. 기본 10([[REQ-012]]) |
| updated_at | datetime | ✔ | 마지막 수정 시각 |

※ 화이트리스트는 별도 필드로 두지 않고 [[DAT-005]](Watchlist)의 `status ≠ 'excluded'` 행을 참조한다(이중 관리 방지).

## 인덱스 및 제약조건

- PK: `id`. 행 수 = 1 강제(`id = 'default'` CHECK).
- 값 제약: `per_order_limit_* > 0`, `daily_loss_limit < 0`, `0 < cash_ratio_min < 1`, `0 < correlation_max ≤ 1`, `sample_min ≥ 1`.
- 이 테이블의 모든 값 변경은 [[DAT-010]](RuleChange)에 1행씩 기록한다.

## API 데이터 규격

예시 1행:
```json
{
  "id": "default",
  "per_order_limit_real": 200000, "per_order_limit_paper": 500000,
  "daily_loss_limit": -50000,
  "stop_file_path": "C:/gujiga/STOP",
  "cash_ratio_min": 0.30, "correlation_max": 0.70, "sample_min": 10,
  "updated_at": "2026-11-24T00:00:00+09:00"
}
```

## 마이그레이션 영향도

- 신규 테이블. 최초 배포 시 기본값 1행을 시드(seed)로 넣는다. 주문 검사([[REQ-003]]·[[REQ-004]]·[[REQ-015]]) 전부가 이 행을 읽으므로, 행이 없으면 모든 주문을 차단하는 안전 동작으로 처리한다.
