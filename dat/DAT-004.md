## 상위 근거

**REQ-003 — 주문 한도 검사: 1회 한도(관직 연동)·하루 손실 -5만원 차단**

**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 1회 주문 금액과 하루 손실이 정해진 숫자를 넘으면 주문이 차단된다.**
사람이 실수로 '실행'을 눌러도 피해가 한도 안에 머물도록, 금액 한도를 시스템이 강제한다.
주문 금액이 1회 한도(실전 20만원 — 관직 연동, 모의 50만원)를 초과하거나, 실전 총평가가 당일 시작 대비 -5만원 이하인 상태의 실전 매수는 차단된다.
- 현재 관직([[REQ-013]])과 당일 시작 시점의 실전 총평가 금액이 기록되어 있다.

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 거래일마다 "당일 시작 시점"의 계좌 상태를 사진처럼 1행 남긴다 — 하루 손실 -5만원 판정의 비교 기준점.**

`daily_account_snapshot` — 근거: [[REQ-003]](당일 시작 대비 -5만원 판정의 분모), [[REQ-015]](현금 비중 30% 계산의 기준 데이터).

## 필드 정의 및 타입

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string(ULID) | ✔ | PK |
| snapshot_date | date | ✔ | 거래일 |
| account_type | enum(real, paper) | ✔ | 실전/모의 |
| start_total_eval | int(원) | ✔ | 당일 시작 총평가 = 현금 + 보유 종목 평가액(지금 전부 팔면 손에 쥐는 금액) |
| start_cash | int(원) | ✔ | 당일 시작 현금 |
| created_at | datetime | ✔ | 기록 시각(개장 전 1회) |

## 인덱스 및 제약조건

- PK: `id`. **UNIQUE: `(snapshot_date, account_type)`** — 하루에 계좌당 1행만.
- 값 제약: `start_total_eval = start_cash + 보유 종목 평가액` 정합. 거래일에만 생성(휴장일 없음).
- 하루 손실 판정: `현재 총평가 − start_total_eval ≤ daily_loss_limit`(GuardConfig)이면 실전 매수 차단([[REQ-003]] AC3).
- 스냅샷이 없는 날은 안전 우선 — 실전 매수를 차단한다(REQ-003 예외 규칙).

## API 데이터 규격

예시 1행:
```json
{
  "id": "01JD8V0001", "snapshot_date": "2026-11-24",
  "account_type": "real",
  "start_total_eval": 787000, "start_cash": 300000,
  "created_at": "2026-11-24T08:30:30+09:00"
}
```

## 마이그레이션 영향도

- 신규 테이블. 08:31 브리핑([[REQ-005]]) 직전(08:30 경)에 자동 생성하는 배치가 필요하다. 과거일 데이터는 없어도 무방(당일 판정에만 사용).
