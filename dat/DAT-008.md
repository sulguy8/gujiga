## 상위 근거

**REQ-011 — 가설 생애주기·증거 기록 관리**

**NTE-004 — 패턴 가설 검증 장부: 가설→검증 중→검증됨/폐기**
**한 줄 요약: 매매 아이디어를 가설 → 검증 중 → 검증됨/폐기 단계로 관리하며 증거를 날짜별로 쌓는다.** (전문: `octet context NTE-004`)
**한 줄 요약: 매매 가설을 분류(A~E)·상태(가설→검증 중→검증됨/폐기)·증거(날짜+한 줄)로 관리하는 장부를 만든다.**
몇 번의 우연을 법칙으로 착각하지 않도록, 가설은 증거가 쌓여야만 믿는 구조를 시스템으로 강제한다.
가설 장부는 각 가설을 분류(A 하루 안 타이밍 / B 이벤트·수급 / C 시장 판단 / D 걸러내기 / E 차트)와 상태(가설→검증 중→검증됨/폐기)로 관리하고, 증거를 날짜와 함께 한 줄씩 누적 기록한다.
- 없음(다른 기능과 독립적으로 동작).

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 매매 가설 1개 = 1행. 분류(A~E)와 상태(가설→검증 중→검증됨/폐기)를 들고 다니는 가설 장부의 본체.**

`hypothesis` — 근거: [[REQ-011]](생애주기), [[REQ-012]](표본 10건 미만 승격 차단).

## 필드 정의 및 타입

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string | ✔ | PK, `HYP-###` 형식 |
| category | enum(A, B, C, D, E) | ✔ | A 하루 안 타이밍 / B 이벤트·수급 / C 시장 판단 / D 걸러내기 / E 차트 |
| statement | string | ✔ | "조건 → 기대 결과" 형식의 가설 진술 |
| status | enum(hypothesis, testing, verified, discarded) | ✔ | 가설/검증 중/검증됨/폐기 |
| evidence_count | int | ✔ | 증거 수(Evidence 집계의 캐시, 기본 0) |
| reference_only | bool | ✔ | '참고 수준' 라벨(= evidence_count < 10, 파생값) |
| created_at | datetime | ✔ | 등록 시각 |
| status_changed_at | datetime | — | 마지막 상태 전이 시각 |

## 인덱스 및 제약조건

- PK: `id`. 인덱스: `(category, status)`.
- 값 제약: `category`·`statement` NOT NULL([[REQ-011]] AC1). 상태 전이는 `hypothesis→testing→(verified|discarded)`만 허용 — 직행(hypothesis→verified) 거부.
- **`status='verified'`로의 전이는 `evidence_count ≥ 10`일 때만 허용**([[REQ-012]] — sample_min은 [[DAT-003]]에서 읽음).
- `discarded` 행도 삭제 금지(같은 착각 반복 방지 — 조회 가능해야 함).
- `evidence_count`·`reference_only`는 [[DAT-009]](Evidence) 삽입·삭제 시 실시간 재계산.
