## 상위 근거

**REQ-011 — 가설 생애주기·증거 기록 관리**

**NTE-004 — 패턴 가설 검증 장부: 가설→검증 중→검증됨/폐기**
**한 줄 요약: 매매 아이디어를 가설 → 검증 중 → 검증됨/폐기 단계로 관리하며 증거를 날짜별로 쌓는다.** (전문: `octet context NTE-004`)
**한 줄 요약: 매매 가설을 분류(A~E)·상태(가설→검증 중→검증됨/폐기)·증거(날짜+한 줄)로 관리하는 장부를 만든다.**
몇 번의 우연을 법칙으로 착각하지 않도록, 가설은 증거가 쌓여야만 믿는 구조를 시스템으로 강제한다.
가설 장부는 각 가설을 분류(A 하루 안 타이밍 / B 이벤트·수급 / C 시장 판단 / D 걸러내기 / E 차트)와 상태(가설→검증 중→검증됨/폐기)로 관리하고, 증거를 날짜와 함께 한 줄씩 누적 기록한다.
- 없음(다른 기능과 독립적으로 동작).

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 가설에 붙는 증거 1건 = 1행. "날짜 + 한 줄"의 가벼운 기록으로, 성공도 실패도 똑같이 쌓는다.**

`evidence` — 근거: [[REQ-011]](증거 축적), [[REQ-012]](표본 수의 집계 원천).

## 필드 정의 및 타입

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string(ULID) | ✔ | PK |
| hypothesis_id | string | ✔ | FK → hypothesis.id |
| evidence_date | date | ✔ | 사례 발생일(날짜 없는 증거는 거부 — [[REQ-011]] AC3) |
| note | string | ✔ | 한 줄 내용(10초 안에 쓸 수 있는 가벼운 기록) |
| outcome | enum(success, fail) | ✔ | 가설 예측이 맞았는지(성공/실패 모두 기록) |
| symbol | string(6) | — | 관련 종목(있으면) |
| created_at | datetime | ✔ | 기록 시각 |

## 인덱스 및 제약조건

- PK: `id`. 인덱스: `(hypothesis_id, evidence_date)`.
- 값 제약: `hypothesis_id`·`evidence_date`·`note`·`outcome` NOT NULL.
- 삽입·삭제 시 상위 [[DAT-008]]의 `evidence_count`·`reference_only`를 재계산한다 — 10건 미만으로 되돌아가면 '참고 수준' 라벨 복원([[REQ-012]] AC4).

## 마이그레이션 영향도
