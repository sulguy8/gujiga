## 상위 근거

**REQ-011 — 가설 생애주기·증거 기록 관리**

**NTE-004 — 패턴 가설 검증 장부: 가설→검증 중→검증됨/폐기**
**한 줄 요약: 매매 아이디어를 가설 → 검증 중 → 검증됨/폐기 단계로 관리하며 증거를 날짜별로 쌓는다.** (전문: `octet context NTE-004`)
**한 줄 요약: 매매 가설을 분류(A~E)·상태(가설→검증 중→검증됨/폐기)·증거(날짜+한 줄)로 관리하는 장부를 만든다.**
몇 번의 우연을 법칙으로 착각하지 않도록, 가설은 증거가 쌓여야만 믿는 구조를 시스템으로 강제한다.
가설 장부는 각 가설을 분류(A 하루 안 타이밍 / B 이벤트·수급 / C 시장 판단 / D 걸러내기 / E 차트)와 상태(가설→검증 중→검증됨/폐기)로 관리하고, 증거를 날짜와 함께 한 줄씩 누적 기록한다.
- 없음(다른 기능과 독립적으로 동작).

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 매매 규칙 숫자가 바뀔 때마다 1행 — "이 규칙이 어느 가설·어떤 근거에서 왔는지"를 되짚는 추적 테이블.**

`rule_change` — 근거: [[REQ-011]](가설 승격 시 이력 기록). [[DAT-003]](GuardConfig) 값 변경도 전부 여기에 남는다.

## 필드 정의 및 타입

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string(ULID) | ✔ | PK |
| rule_key | string | ✔ | 바뀐 규칙 키(예: `guard.per_order_limit_real`) |
| old_value | string | ✔ | 변경 전 값(문자열 직렬화) |
| new_value | string | ✔ | 변경 후 값 |
| reason | string | ✔ | 변경 이유 한 줄 |
| source_hypothesis_id | string | — | FK → hypothesis.id(가설 승격 유래 변경이면 필수) |
| changed_by | string | ✔ | 변경 주체(사람 이름 — 규칙 변경은 사람만) |
| changed_at | datetime | ✔ | 변경 시각 |

## 인덱스 및 제약조건

- PK: `id`. 인덱스: `(rule_key, changed_at)`.
- 값 제약: 가설 승격에서 비롯된 변경은 `source_hypothesis_id` NOT NULL([[REQ-011]] AC5) — 그 가설은 `status='verified'`여야 한다.
- 추가 전용(append-only) — 이력은 수정·삭제하지 않는다.
