## 상위 근거

**REQ-013 — 관직·승진·군령 위반 초기화 관리**

**NTE-005 — 삼국지 게임 레이어: 병력·관직·성벽으로 규칙 준수 게임화**
**한 줄 요약: 매매 규칙을 삼국지 게임 용어(병사·관직·성벽·포로)로 입혀서, 규칙 지키기를 의무가 아니라 게임처럼 재미있게 만든다.**
규칙 기반 매매의 최대 적은 규칙 자체가 아니라 "규칙을 지키기 싫어지는 마음"이다. 이미 군주·출사표 같은 삼국지 세계관을 쓰고 있으므로, 이를 앱 전반의 게임 레이어로 확장해 규칙 준수 자체에 재미와 명예를 부여한다.
매매 개념을 삼국지 용어로 1:1 대응시킨다.
1. **병력 환산**: 1만원 = 병사 1명. 투자금이 곧 병력이라 "이 전투(종목)에 몇 명을 보낼까"로 자금 관리를 직관화한다.
2. **관직과 권한**: 관직에 따라 한 종목 최대 병력(종목당 투자 상한)과 동시 종목 수(전선 수)가 제한된다. 승진 조건은 성과가 아니라 **규칙 준수 실적** 중심이다.

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 현재 관직·승진 진행 상황(general_rank, 1행)과 군령 위반 기록(violation, N행) — 서로 떼기 어려운 한 쌍이라 군주 지시로 한 카드에 담는다.**

※ 엄밀히는 테이블 2개다(원자성 예외 — `octet check`에서 DAT_MULTI 경고가 뜰 수 있으나 군주가 합치기로 결정). 근거: [[REQ-013]].

## 필드 정의 및 타입

**general_rank** (1행 — 현재 관직 상태):

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string | ✔ | PK, 고정값 `"me"`(1행) |
| rank | enum(hyeonryeong, taesu, jasa, daejanggun, seungsang) | ✔ | 현령/태수/자사/대장군/승상 |
| per_stock_troops_max | int | ✔ | 한 종목 최대 병력(20/30/40/50/재량) |
| concurrent_max | int | ✔ | 동시 종목 수(2/3/4/5/재량) |
| sortie_count | int | ✔ | 승진 카운트 — 출사표 출병 횟수(위반 시 0으로) |
| clean_weeks | int | ✔ | 연속 무위반 주수(위반 시 0으로) |
| review_weeks | int | ✔ | 주간 복기 수행 주수(위반 시 0으로) |
| promoted_at | datetime | — | 마지막 승진 시각 |
| updated_at | datetime | ✔ | 갱신 시각 |

**violation** (N행 — 군령 위반 기록, 추가 전용):

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | string(ULID) | ✔ | PK |
| violation_date | date | ✔ | 위반일 |
| code | enum(V1_no_draft, V2_stop_exit_missed, V3_revenge, V4_correlation, V5_ration) | ✔ | 위반 5종: ①출사표 없이 출병 ②손절 매도 기한 미이행 ③복수 매매 ④상관 0.7 동시 보유 ⑤현금 30% 미만 |
| context | string | ✔ | 당시 상황 한 줄 |
| order_log_id | string | — | FK → order_log.id(관련 주문) |
| created_at | datetime | ✔ | 기록 시각 |

## 인덱스 및 제약조건

- general_rank: PK `id`, 행 수 1. rank↔한도 값은 관직 표([[REQ-013]])와 일치해야 하며, rank 변경 시 [[DAT-003]]의 `per_order_limit_real`을 동기화(현령 20만→태수 30만…).
- violation: PK `id`, 인덱스 `(violation_date)`, `(code)`. 추가 전용(수정·삭제 금지).
- 연동 규칙: violation INSERT 시 general_rank의 `sortie_count`·`clean_weeks`·`review_weeks`를 0으로 리셋([[REQ-013]] AC3). V3~V5는 [[REQ-015]] 차단을 우회(강제 실행)한 경우에만 INSERT.

## 마이그레이션 영향도
