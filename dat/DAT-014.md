## 상위 근거

**REQ-028 — 책사 7인 의견 생성** · [[REQ-030]](채점) · [[REQ-031]](불일치율)

## 엔티티 스키마 (단일 테이블)

**한 줄 요약: 책사가 낸 모든 의견과 그 채점 결과를 한 줄씩 쌓기만 하는(append-only, 수정·삭제 없음) 판정 장부.**

- 엔티티: CouncilVerdict (책사 판정 1건 = 레코드 1건)
- 저장: `%USERPROFILE%\gujiga-data\council\verdicts.jsonl` (JSON Lines — 한 줄에 레코드 하나, 추가만 허용). 운영 장부는 저장소(코드 레포) 밖에 둔다 — 레포 안 `trading/` 경로를 쓰지 않는다.

## 필드 정의 및 타입

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 레코드 ID (예: `CV-20261126-0001`) |
| date | string(YYYY-MM-DD) | 의견 기록일 |
| agenda_id | string | 안건 ID(같은 안건의 7+1건을 묶음) |
| ticker / name | string | 종목코드·종목명 (예: 와이씨) |
| agenda_type | enum | `entry`(신규 진입 검토) \| `hold`(보유 점검) |
| advisor | enum | 곽가·노숙·순욱·법정·육손·장송·가후·제갈량 |
| stance | enum | `출병` \| `관망` \| `반대` \| `회군` |
| confidence | int(1~5) | 확신 |
| rationale | string | 한 줄 근거 |
| source | enum | `rule`(숫자 규칙) \| `ai` \| `fallback`(엔진 불가 폴백) \| `synthesis`(제갈량 종합) |
| rank_at_time | object | 기록 시점 관직·가중치 `{rank, weight}` (사후 소급 금지) |
| score_result | enum | `pending` \| `hit` \| `miss` \| `excluded` |
| rel_return | number\|null | 채점 시 상대 수익률(종목 − KODEX 200, %) |
| scored_at | string\|null | 채점 확정일 |
| disagreement | number\|null | 안건 불일치율(%) — 제갈량(synthesis) 레코드에만 기록 |
| created_at | string(ISO) | 기록 시각 |

## 인덱스 및 제약조건

- **append-only**: 수정·삭제 금지. 채점 확정은 "채점 필드가 채워진 정정 레코드"를 추가하는 방식이 아니라, pending 레코드를 쓴 뒤 채점 배치가 `score` 이벤트 라인(`{type:"score", verdict_id, score_result, rel_return, scored_at}`)을 덧붙이는 이벤트 방식 — 원본 의견 줄은 영원히 불변.
- 유일성: (agenda_id, advisor) 조합당 의견 1건. (verdict_id)당 score 이벤트 1건(멱등).
- stance=`회군`은 agenda_type=`hold`에서만 유효.
- 유효 의견(폴백 제외)이 4건 미만이라 제갈량 종합이 생략된 안건은 불일치율(disagreement)을 기록하지 않는다 — 불일치율 집계에서도 제외.

## API 데이터 규격

- 조회: 날짜·책사·안건별 필터로 읽기 전용 제공(의견판 [[SCR-009]]·공적판 [[SCR-010]]).
- 쓰기: 책사단 엔진([[ARC-010]])과 채점 배치만 append 가능. 주문 경로에서는 접근 불가.

## 마이그레이션 영향도

- 신규 파일 — 기존 장부와 충돌 없음. Aside 시범 기록(`trading/reports/날짜.json`의 council 배열, 첫 표본 2026-11-26 와이씨)을 [[TSK-028]]로 이관해 초기 데이터로 삼는다.
