## 배경 및 맥락

**한 줄 요약: 데몬이 로컬 claude CLI를 헤드리스(`claude -p`, OCTET chat.js와 같은 방식)로 호출해 해석·초안·건의를 만드는 "군사(軍師) 엔진"을 둔다 — 판단 제안은 AI, 실행은 사람.**

규칙 엔진은 숫자 판정(날씨·신호등·성벽)은 잘하지만 "왜"와 "말"은 못 만든다. 현행 Aside 군의에서 사람이 읽던 해석 품질을 앱에서도 유지하려면 LLM 호출 계층이 필요하다.

## 아이디어 / 논의 내용

군사 엔진의 4기능:

1. **08:31 군의 해석**: 시장 2줄 + 신호등 근거 + 오늘 작전을 생성(규칙 엔진의 숫자 판정을 입력으로 받아 말로 풀이).
2. **출사표 초안 작성**: [[DAT-001]]에 `created_by='ai'`, `user_confirmed=false`로만 기록 — 실행 플래그는 절대 건드리지 못한다.
3. **전략 변경 건의**: 군주 상시 명령 4기준에 해당할 때만 — ① 출병 조건 종일 불가 ② 성벽 이탈 ③ 지수 예상 반대 ±2% ④ 중대 공시·뉴스.
4. **결정 순간 삼국지 통찰**: 일화 1~2개 + 상·중·하책 표 + 추천 1개(최종 선택은 군주).

제약(안전·비용):
- **권한**: AI 도구는 읽기 + 초안 쓰기만. 주문 함수·실행 확인 플래그 접근 불가([[REQ-002]]와 같은 불변식).
- **인젝션 방지**: 뉴스·웹 텍스트는 데이터로만 취급 — 그 안의 지시문을 명령으로 따르지 않는다.
- **비용 상한**: LLM 호출은 군의 1회·전황(15:05) 1회·척후는 규칙 엔진이 [액션 필요] 판정한 회차만. 하루 최대 횟수 설정값.
- **degrade**: claude CLI가 없거나 실패하면 규칙 엔진만으로 최소 보고(숫자 판정 + 고정 문구).

## 결정사항

군사 엔진은 로컬 claude CLI 헤드리스 호출로 구현하고, 권한은 "읽기+초안 쓰기", 호출은 정시 2회+[액션 필요] 회차로 상한을 둔다. 이유: 해석 품질은 LLM으로, 돈이 걸린 실행 경로와 비용은 구조적으로 통제하기 위함.
