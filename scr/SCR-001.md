## 상위 근거

**DAT-001 — 출사표 OrderDraft**

**REQ-001 — 출사표 필수 5항목 검증**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 출사표(주문 초안)는 5가지 항목이 모두 채워져야만 성립한다.**
출사표는 모든 주문의 출발점이다. 항목이 빠진 채 주문이 나가면 손절선 없는 매매 같은 사고로 이어지므로, 성립 요건을 시스템이 강제한다.
모든 출사표는 ① 진입 가격대 ② 손절선 ③ 목표가 ④ 기한 ⑤ 병력 수(투입 금액)의 5개 항목이 전부 채워져야 제출(저장)될 수 있다.

## 화면 목적 (단일 화면)

**한 줄 요약: '옥새 찍는 곳' — 출사표 한 장을 눈으로 확인하고, 모든 검사 결과를 본 뒤, 사람만이 '실행'(옥새)을 눌러 출병시키는 모달.**

화면 이름을 "출사표 확인·실행 창"에서 **"옥새 찍는 곳"**으로 바꾼다(지령 016 — **용어만** 바꾸고, 보안 문구·확인 절차는 한 글자도 줄이지 않는다).

실전 주문이 나가는 유일한 관문이다. AI는 이 모달을 열 수만 있고, '실행'은 사람 손으로만 눌린다([[REQ-002]]).

## UI/UX 흐름 및 인터랙션

- 진입 경로: 출사표 목록/알림에서 출사표 선택 → 모달 열림. (PC·모바일 공통, 모바일은 전체 화면 시트)
- 사용자 동작: ① 내용 확인 → ② 검사 결과 확인 → ③ [실행] 또는 [반려] 또는 [닫기].
- [실행]: 길게 누르기(1초) 또는 2단 확인("출병시키겠습니까?") — 오터치 방지. 누르면 `user_confirmed=true` 기록 후 전송.
- [반려]: 출사표 status를 cancelled로. 사유 한 줄 입력(선택).

## 에러/빈 상태 연출

- 검사 1개라도 ❌: [실행] 버튼 비활성 + 걸린 검사명과 현재 수치 표시(예: "군량 부족 — 매수 후 현금 27%").
- STOP 파일 존재: 모달 상단에 "전군 정지 중" 띠 + [실행] 비활성.
- 5항목 누락 출사표(비정상 유입): "출사표 불성립 — 손절선 없음" 표시, 실행 불가.
- 전송 실패(증권사 오류): 실패 사유 표시 + 수동 HTS 주문 안내(RSK-002 대응).

## 수용 기준 (AC)

1. `user_confirmed=false`인 상태에서는 어떤 경로로도 전송이 일어나지 않는다.
2. 검사 ❌가 하나라도 있으면 [실행]이 비활성이고, 사유와 수치가 표시된다.
3. [실행] 확정 시 `confirmed_at`이 기록되고 주문이 전송된다.
4. 모바일에서도 5항목과 검사 결과가 스크롤 없이(또는 1스크롤 내) 보인다.

## 지령 016 개편 (현황판 게임 화면·용어)

- 화면 이름: "출사표 확인·실행 창" → **"옥새 찍는 곳"**(화면 문구만).
- **보안 문구·확인 절차는 줄이지 않는다**: 길게 누르기(1초)/2단 확인("출병시키겠습니까?"), 검사 결과판(한도·군령 ✅/❌ 전체 목록), `user_confirmed` 기록, STOP "전군 정지 중" 띠 — 모두 그대로. 바뀌는 것은 표기 용어뿐(예: 손절선(성벽) → 성벽, 목표가 → 깃발).
- 이 화면은 '참고용'이 아니라 실전 주문이 나가는 유일한 관문 — "실행은 사람만" 원칙 문구를 그대로 유지한다.

### 공통 규칙(지령 016)

- 화면 문구는 아래 용어표대로 바꾼다. **화면에 보이는 말만 바꾸고, 데이터 필드명·장부 구조는 그대로** 둔다.
- 화면 문구 사전은 `src/ui_terms.js` **한 파일**로 모아 관리한다(화면마다 하드코딩 금지 — 사전만 바꾸면 일괄 교체).
- 읽기 전용·보안 규칙·"참고용, 최종 결정은 군주" 문구는 그대로 유지한다.
- 나라 색: 촉 초록 · 위 파랑 · 오 빨강. 밝은 베이지 톤 유지, 그라데이션·그림자·이모지 최소/금지. 모바일 폭 380px에서도 깨지지 않게.
- 숫자는 장부 값 그대로(꾸미지 않음). 틀린 숫자를 예쁘게 그리지 않는다(지령 015 데이터 수리 선행).
- 시안: `_campaign/orders/016-시안.html` (숫자는 2026-11-26 실제 값 예시).
