## 상위 근거

**DAT-008 — 가설 Hypothesis**

**REQ-011 — 가설 생애주기·증거 기록 관리**
**NTE-004 — 패턴 가설 검증 장부: 가설→검증 중→검증됨/폐기**
**한 줄 요약: 매매 아이디어를 가설 → 검증 중 → 검증됨/폐기 단계로 관리하며 증거를 날짜별로 쌓는다.** (전문: `octet context NTE-004`)
**한 줄 요약: 매매 가설을 분류(A~E)·상태(가설→검증 중→검증됨/폐기)·증거(날짜+한 줄)로 관리하는 장부를 만든다.**
몇 번의 우연을 법칙으로 착각하지 않도록, 가설은 증거가 쌓여야만 믿는 구조를 시스템으로 강제한다.
가설 장부는 각 가설을 분류(A 하루 안 타이밍 / B 이벤트·수급 / C 시장 판단 / D 걸러내기 / E 차트)와 상태(가설→검증 중→검증됨/폐기)로 관리하고, 증거를 날짜와 함께 한 줄씩 누적 기록한다.

## 화면 목적 (단일 화면)

**한 줄 요약: 병법서 — 매매 가설을 목록으로 훑고, 한 권을 펼치면(상세) 증거를 한 줄씩 쌓는 화면.**

목록과 상세는 한 화면의 마스터-디테일 구성(PC: 좌우 분할, 모바일: 목록→상세 전환)으로, 군주 지시에 따라 SCR 1건으로 묶는다. 근거: [[REQ-011]]·[[REQ-012]].

## UI/UX 흐름 및 인터랙션

- 진입 경로: 홈 → '병법서'. 증거 기록은 장 마감 후 복기 때 주로 사용.
- 사용자 동작(목록): 분류(A~E)·상태 필터, 가설 탭 → 상세. [새 가설] 등록(분류+조건→기대 결과 필수).
- 사용자 동작(상세): [증거 추가] — 날짜+한 줄+성공/실패, 10초 안에 끝나는 입력. 상태 전이 버튼(검증 중/검증됨/폐기 — 순서 강제). 검증됨 가설에는 [규칙으로 승격] 버튼 → RuleChange 기록 안내.

## 컴포넌트 구조

| 구역 | 내용 |
|---|---|
| (목록) 필터 | 분류 A~E 칩 · 상태 칩 |
| (목록) 가설 행 | 분류 · 진술 요약 · 상태 배지 · 증거 N건 · '참고 수준' 라벨 |
| (상세) 머리 | 진술 전체 · 상태(등급) · **표본 진행 막대(N/10) + 출병 증거 n/3**([[REQ-025]]) · 판정식(있으면) · 등급별 병력 상한 표시([[REQ-023]]) |
| (상세) 증거 표 | 1행 = 날짜 · 한 줄 · 성공/실패 · 종목 |
| (상세) 하단 | [증거 추가] · 상태 전이 · [규칙으로 승격] |

## 데이터 바인딩

| 표시 항목 | 원천 |
|---|---|
| 분류·진술·상태 | DAT-008 `hypothesis` (category, statement, status) |
| '참고 수준' 라벨·표본 진행 | `hypothesis.reference_only, evidence_count` (기준 10은 DAT-003 `sample_min`) |
| 증거 행 | DAT-009 `evidence` (evidence_date, note, outcome, symbol) |
| 승격 이력 | DAT-010 `rule_change` (source_hypothesis_id로 역참조) |

## 에러/빈 상태 연출

- 가설 0건: "병법서가 비어 있습니다 — 첫 가설을 기록하세요".
- 증거 9건 이하에서 [검증됨] 시도: 차단 + "표본 부족(N/10)" 안내([[REQ-012]]).
- 허용되지 않은 전이(가설→검증됨 직행): 버튼 자체를 비활성.
- 폐기 가설: 회색 처리하되 목록·검색에서 계속 조회 가능.

## 수용 기준 (AC)

1. 분류 없이 가설 등록이 불가능하다.
2. 증거 10건 미만 가설에 '참고 수준' 라벨이 보이고 [검증됨]이 차단된다.
3. 증거 추가 입력이 날짜+한 줄+성공/실패 3칸으로 끝난다.
4. [규칙으로 승격] 시 rule_change에 가설 ID가 기록된 것을 확인할 수 있다.
