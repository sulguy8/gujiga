## 상위 근거

**DAT-003 — 안전 설정 GuardConfig**

**REQ-003 — 주문 한도 검사: 1회 한도(관직 연동)·하루 손실 -5만원 차단**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 1회 주문 금액과 하루 손실이 정해진 숫자를 넘으면 주문이 차단된다.**
사람이 실수로 '실행'을 눌러도 피해가 한도 안에 머물도록, 금액 한도를 시스템이 강제한다.
주문 금액이 1회 한도(실전 20만원 — 관직 연동, 모의 50만원)를 초과하거나, 실전 총평가가 당일 시작 대비 -5만원 이하인 상태의 실전 매수는 차단된다.

## 화면 목적 (단일 화면)

**한 줄 요약: 모든 안전장치 숫자를 한 화면에서 보고(읽기 중심), 긴급 시 전군 정지(STOP)를 거는 군율(軍律) 화면.**

숫자는 함부로 바꾸는 곳이 아니라 "지금 어떤 군율이 적용 중인지" 확인하는 곳이다. 근거: [[REQ-003]]·[[REQ-004]].

## UI/UX 흐름 및 인터랙션

- 진입 경로: 홈 → 설정 → '군율'. STOP은 앱 어디서든 접근 가능한 비상 버튼으로도 노출.
- 사용자 동작: 군율 숫자 열람. [전군 정지] — 2단 확인 후 STOP 파일 생성, [정지 해제] — 2단 확인 후 삭제. 숫자 수정은 수정 사유 입력 필수(RuleChange 기록) — 수정 가능 주체는 사람만.
- 예외: **실전 1회 한도(per_order_limit_real)는 이 화면에서 수정 불가(읽기 전용)** — [[REQ-003]]·[[REQ-013]]·[[DAT-011]]에 따라 관직에서만 정해지는 값이므로, "관직 연동 — 승진 시 자동 상향" 안내만 표시한다.

## 컴포넌트 구조

| 구역 | 내용 |
|---|---|
| STOP 카드 | 현재 상태(정상/전군 정지 중) · [전군 정지]/[정지 해제] 버튼 |
| 군율 표 | 실전 1회 한도(🔒 읽기 전용, "관직 연동 — 승진 시 자동 상향" 안내) · 모의 1회 한도 · 하루 손실 한도 · 군량 최소 % · 상관 상한 · 표본 최소 |
| 화이트리스트 안내 | "실전 매수 가능 성 = 관심 종목(제외 제외) N곳" + 관심 종목 화면 링크 |
| 변경 이력 | 최근 군율 변경 N건(rule_change) |

## 에러/빈 상태 연출

- STOP 활성: 화면 전체 상단에 빨간 "전군 정지 중 — 모든 주문 차단" 띠(앱 전역 공통).
- STOP 파일 검사 실패(파일 시스템 오류): "정지 상태 확인 불가 — 안전을 위해 주문 차단 중" 표시([[REQ-004]] 예외 규칙).
- guard_config 행 없음(비정상): 모든 값 "미설정" + 주문 전면 차단 안내.

## 수용 기준 (AC)

1. [전군 정지] 확정 후 다음 주문 시도부터 실전·모의 모두 차단되고, 해제 후 재개된다.
2. 군율 표의 숫자가 guard_config 현재 값과 항상 일치한다.
3. 숫자 수정 시 사유 없이는 저장되지 않고, 저장되면 rule_change에 1행이 남는다.
4. 모바일에서 STOP 버튼이 두 번의 탭 이내로 도달 가능하다.
5. 실전 1회 한도는 화면에서 수정할 수 없다(읽기 전용 — 관직 승진으로만 변경되며, "관직 연동 — 승진 시 자동 상향" 안내가 표시된다).
