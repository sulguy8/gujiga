## 상위 근거

**ARC-002 — 저장소: 파일(md·jsonl)+Git 유지**

**DAT-002 — 주문·체결 로그 OrderLog**
**REQ-002 — 실전 주문 사용자 '실행' 확인 필수**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 실전 주문은 사람이 '실행'을 확인한 경우에만 증권사로 나간다 — AI 단독 주문은 구조적으로 불가능해야 한다.**
실전 계좌는 진짜 돈이 움직인다. AI가 오작동해도 돈이 나가지 않도록, 사람의 확인을 주문 전송의 필수 관문으로 만든다.

## 작업 목적

**목표: 모든 장부의 바탕이 되는 파일 저장소 구조와 append-only(추가 전용) 원장 유틸을 만든다.** [1단계 기반 · 규모 M · 담당: Claude Code 구현 / 군주 확인]

## 상세 구현 범위

산출물:
- 데이터 디렉터리 구조(DAT 12건의 파일 배치: 원장 jsonl / 상태 json·md, 월별 분할 규칙)
- `ledger.append()` 유틸 — jsonl 1행 추가 전용, 수정·삭제 API 없음
- `state.read()/write()` 유틸 — 상태 파일 덮어쓰기 + Git 커밋
- 기동 시 정합성 검사(원장 재계산과 상태 값 대조) 뼈대

## 수용 조건 (AC)

1. 원장 유틸에 수정·삭제 함수가 존재하지 않는다(append만 노출).
2. DAT-002 예시 1행을 append → 파일에 jsonl 1행이 추가되고 재호출 시 이어 붙는다.
3. 정합성 검사가 일부러 어긋낸 상태 파일을 감지해 경고를 출력한다.
4. 외부 패키지 의존 0(Node 내장만).
