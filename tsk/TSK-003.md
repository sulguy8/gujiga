## 상위 근거

**ARC-003 — 증권사 연동: KIS 어댑터와 단일 주문 게이트**

**SCR-001 — 출사표 확인·실행 모달**
**DAT-001 — 출사표 OrderDraft**
**REQ-001 — 출사표 필수 5항목 검증**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 출사표(주문 초안)는 5가지 항목이 모두 채워져야만 성립한다.**

## 작업 목적

**목표: 검증된 kis_client.js를 `kis-adapter` 모듈로 계승·정리한다 — 토큰 캐시(암호화)·1.2초 호출 간격·모의/실전 분기를 어댑터 안에 가둔다.** [1단계 기반 · 규모 M · 담당: Claude Code 구현 / 군주 확인(모의 호출)]

## 상세 구현 범위

산출물:
- `kis-adapter` 모듈: 시세 조회·주문·정정·취소·체결조회 함수(현행 kis_client.js 로직 이식)
- 토큰 관리: 발급·캐시(TSK-002 암호화 유틸 경유)·만료 시 1회 재발급 재시도(무한 재시도 금지)
- 호출 간격 1.2초 보장 큐(현행 관습 계승)
- 모의/실전 도메인 분기는 어댑터 내부에서만(밖에서는 account_type만 전달)

## 수용 조건 (AC)

1. 모의 도메인에서 시세 조회·주문·정정·취소·체결조회가 각 1회 이상 정상 동작한다.
2. 연속 호출 시 호출 간격이 1.2초 미만으로 좁혀지지 않는다(로그 타임스탬프 확인).
3. 토큰·키가 어댑터 모듈 밖으로 반환되는 API가 없다(코드 리뷰).
4. 실전 도메인 주문 함수는 존재하되 이 단계에서는 호출 경로가 비활성이다(TSK-012에서 활성화).
