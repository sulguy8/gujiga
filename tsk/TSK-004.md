## 상위 근거

**DAT-011 — 관직·군령 위반 GeneralRank·Violation**

**REQ-013 — 관직·승진·군령 위반 초기화 관리**
**NTE-005 — 삼국지 게임 레이어: 병력·관직·성벽으로 규칙 준수 게임화**
**한 줄 요약: 매매 규칙을 삼국지 게임 용어(병사·관직·성벽·포로)로 입혀서, 규칙 지키기를 의무가 아니라 게임처럼 재미있게 만든다.**
규칙 기반 매매의 최대 적은 규칙 자체가 아니라 "규칙을 지키기 싫어지는 마음"이다. 이미 군주·출사표 같은 삼국지 세계관을 쓰고 있으므로, 이를 앱 전반의 게임 레이어로 확장해 규칙 준수 자체에 재미와 명예를 부여한다.
매매 개념을 삼국지 용어로 1:1 대응시킨다.
1. **병력 환산**: 1만원 = 병사 1명. 투자금이 곧 병력이라 "이 전투(종목)에 몇 명을 보낼까"로 자금 관리를 직관화한다.

## 작업 목적

**목표: 게이트와 화면이 읽을 도메인 상태 — 군율(guard_config)·관직(general_rank)·위반(violation)·포로 원장(captive_ledger) — 의 계산 로직을 만든다.** [2단계 게이트 · 규모 M · 담당: Claude Code 구현 / 군주 확인(계산 검산)]

## 상세 구현 범위

산출물:
- guard_config 로드·검증(없으면 전면 차단의 안전 동작 — [[DAT-003]])
- general_rank 모듈: 관직 표 한도 조회, 승진 카운트 갱신, 위반 시 카운트 0 초기화([[REQ-013]])
- violation 기록 모듈: 위반 5종 코드(V1~V5), append-only
- captive_ledger 계산: 손실→포로 적립(1만원=1명 반올림), 수익→구출 우선→전공([[REQ-014]])

## 수용 조건 (AC)

1. REQ-014 AC의 수치 예가 그대로 재현된다: -3만원→포로 3, +2만원→포로 1·전공 0, +2만원→포로 0·전공 1만원, 14,000원→1명/16,000원→2명.
2. violation 1건 기록 시 general_rank의 승진 카운트 3종이 0이 된다.
3. guard_config 파일이 없으면 모든 검사 함수가 "차단"을 반환한다.
4. 태수 승진 반영 시 실전 1회 한도 조회값이 30만원으로 바뀐다.
