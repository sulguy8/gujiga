**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 출사표(주문 초안)는 5가지 항목이 모두 채워져야만 성립한다.**

## 작업 목적

**목표: 모든 주문이 통과하는 단일 게이트를 구현한다 — ARC-003의 검사 7단계를 순서대로 수행하고, 걸리면 blocked+사유를 원장에 남긴다.** [2단계 게이트 · 규모 L · 담당: Claude Code 구현 / 군주 확인]

## 상세 구현 범위

산출물:
- `gate.submit(draft)` 단일 진입 함수 — 이 함수 외에 kis-adapter 주문을 부르는 경로가 없도록 모듈 경계 설정
- 검사 7단계(순서 고정): ① STOP 파일 ② 출사표 5항목 ③ 사용자 확인 플래그(실전) ④ 화이트리스트·지정가(실전 매수) ⑤ 1회 한도·하루 손실 ⑥ 군령 3종(군량 30%·복수 매매·상관 0.7) ⑦ 관직 한도
- 차단 시 order_log에 `status=blocked, block_reason` 기록 + 사유·수치 반환
- 통과 시 kis-adapter 전송 → 체결조회(10초 간격 최대 1분) → order_log 기록

## 수용 조건 (AC)

1. AI가 만든 출사표(user_confirmed=false)로 실전 submit → 전송 0건, blocked(no_confirm) 기록.
2. 7단계 각 검사에 대해 차단 사례 1건 이상이 모의에서 재현된다(상세 전수는 [[TSK-006]]).
3. gate를 거치지 않고 어댑터 주문 함수를 호출하는 코드 경로가 없다(코드 리뷰).
4. 통과 주문은 체결조회 결과까지 order_log에 남는다.
