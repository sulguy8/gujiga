## 상위 근거

**ARC-003 — 증권사 연동: KIS 어댑터와 단일 주문 게이트**

**SCR-001 — 출사표 확인·실행 모달**
**DAT-001 — 출사표 OrderDraft**
**REQ-001 — 출사표 필수 5항목 검증**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 출사표(주문 초안)는 5가지 항목이 모두 채워져야만 성립한다.**

## 작업 목적

**목표: 모의 계좌에서 게이트의 차단 사유 전수를 하나씩 일부러 재현해, 안전장치가 실제로 작동함을 증명한다.** [2단계 게이트 · 규모 M · 담당: Claude Code 시나리오 작성·실행 / 군주가 결과 리포트 확인]

## 상세 구현 범위

산출물:
- 차단 시나리오 스크립트: block_reason 10종(no_confirm, per_order_limit, daily_loss, not_whitelisted, market_order, stop_file, nation_limit, ration30, revenge, correlation) 각각을 모의에서 유발
- 통과 시나리오: 정상 출사표 → 사용자 확인 → 모의 체결까지 1건
- 결과 리포트(각 사유별 order_log 증빙 행 링크)

## 수용 조건 (AC)

1. 10개 block_reason 각각에 대해 blocked 기록이 order_log에 1건 이상 존재한다.
2. 차단 전 과정에서 실제 모의 주문이 증권사로 전송된 건수가 0이다(차단은 전송 전 단계).
3. 정상 통과 1건은 모의 체결까지 완료되고 로그가 남는다.
4. 리포트를 군주가 확인·서명(카드 코멘트)한다.
