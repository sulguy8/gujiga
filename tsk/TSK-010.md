## 상위 근거

**SCR-001 — 출사표 확인·실행 모달**

**DAT-001 — 출사표 OrderDraft**
**REQ-001 — 출사표 필수 5항목 검증**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 출사표(주문 초안)는 5가지 항목이 모두 채워져야만 성립한다.**
출사표는 모든 주문의 출발점이다. 항목이 빠진 채 주문이 나가면 손절선 없는 매매 같은 사고로 이어지므로, 성립 요건을 시스템이 강제한다.

## 작업 목적

**목표: 출사표 확인·실행 모달(SCR-001)을 구현한다 — 사람이 '실행'을 누르는 유일한 관문의 UI.** [4단계 화면 · 규모 M · 담당: Claude Code 구현 / 군주 확인(실행 흐름 검수)]

## 상세 구현 범위

산출물:
- 모달 UI: 5항목 표·검사 결과판(7단계 ✅/❌)·[실행]/[반려]/[닫기]
- [실행] 오터치 방지: 길게 누르기(1초) 또는 2단 확인 → user_confirmed=true + confirmed_at 기록 → 게이트 submit
- 검사 ❌ 시 [실행] 비활성 + 사유·수치 표시, STOP 활성 시 "전군 정지 중" 띠
- [반려] 시 출사표 cancelled 처리

## 수용 조건 (AC)

1. 검사 ❌가 하나라도 있으면 [실행]이 비활성이다(모의로 10개 사유 각각 확인 — [[TSK-006]] 시나리오 재사용).
2. [실행] 없이 모달을 닫으면 어떤 주문도 전송되지 않는다.
3. [실행] 확정 시 confirmed_at이 기록되고 게이트를 거쳐 모의 체결까지 이어진다.
4. SCR-001 AC 4건(모바일 1스크롤 제외 — PC 전용 확정으로 PC 레이아웃 기준)이 통과한다.
