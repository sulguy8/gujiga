## 작업 목적

**목표: gujiga 앱의 주문 게이트를 경유하는 실전 경로를 처음으로 검증한다 — 전체 파이프라인의 마지막 관문.** [실전 단계(마지막) · 규모 S · 담당: Claude Code 준비 / **실행 확인은 군주만**]

구분 주의: **KIS 실전 주문 TR 자체의 첫 검증(ARC-003)은 2026-11-24 엘티씨 출병이 현행 kis_client.js로 수행하며 이 TSK와 별개다.** 이 TSK는 "앱의 게이트(검사 7단계)를 거쳐 나가는 실전 경로"의 첫 검증이다. 오늘 현행 도구로 실전 TR이 검증되면(체결조회 성공 여부 포함) 그 결과를 이 작업의 **사전 근거로 참조**한다 — TR이 이미 통한다는 것이 확인된 상태에서 앱 경로만 검증하면 되므로 위험이 한 단계 줄어든다.

## 상세 구현 범위

산출물:
- 앱의 실전 주문 경로 활성화(어댑터의 실전 분기 — [[TSK-003]]에서 비활성으로 둔 것)
- 사전 점검표: STOP 미존재·DPAPI 암호화 상태·대상 종목 화이트리스트 등록·예수금 50만원·한도 설정 확인 + **현행 kis_client.js 실전 TR 검증 결과(2026-11-24 엘티씨 출병의 체결조회 성공 여부) 참조 확인**
- 대상: **그 시점의 첫 출병 종목, 최소 수량** — 특정 종목으로 고정하지 않는다. 실전 출사표 → 군주 '실행' → 체결조회 10초 간격 최대 1분([[ARC-003]] 확정) → 결과 리포트
- 실패 시 수동 HTS 대체 절차 문서화

## 수용 조건 (AC)

1. 선행 조건 충족이 확인된다: [[TSK-006]] 모의 전수 검증 통과 + 모의 2주 무사고([[ARC-004]] 기준) + 현행 도구의 실전 TR 검증 결과 참조.
2. 실전 주문이 앱 게이트(검사 7단계)를 통과하고 군주의 '실행' 확인을 거쳐 전송되며, 체결조회로 체결(또는 미체결 상태)이 확인된다.
3. 전 과정이 order_log에 남고, 앱 경유 첫 실전 결과 리포트가 작성된다.
4. 실패 시: 수동 HTS로 처리하고 실패 원인이 기록된다.
