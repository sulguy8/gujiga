**SCR-008 — 안전 설정·STOP 화면**
**DAT-003 — 안전 설정 GuardConfig**
**REQ-003 — 주문 한도 검사: 1회 한도(관직 연동)·하루 손실 -5만원 차단**
**NTE-001 — 실전 주문 안전장치: AI는 출사표(주문 초안)만, 실행은 사람이**
**한 줄 요약: AI는 주문 제안서(출사표)까지만 만들고, 실제 돈이 나가는 주문은 사람이 '실행' 버튼을 눌러야만 나간다.** (전문: `octet context NTE-001`)
**한 줄 요약: 1회 주문 금액과 하루 손실이 정해진 숫자를 넘으면 주문이 차단된다.**

## 작업 목적

**목표: 허도 관문(127.0.0.1 전용 키 중계 서버)과 Aside용 얇은 kis_client.js를 구현한다 — DPAPI 키를 Aside가 쓸 수 있게 하는 다리.** [기반 보강 · 규모 M · 담당: Claude Code 구현 / Aside trading 폴더 교체는 **군사가 수행** / 군주 확인]

## 상세 구현 범위

산출물:
- **관문 서버**: 127.0.0.1 바인딩(포트 설정값, 제안 62910), 기동 시 무작위 토큰 생성·지정 파일 기록(재기동 시 교체), 요청별 토큰·Host 검사, DPAPI 복호화(메모리만), kis-adapter 경유 KIS 대행(price/balance/fills/order/modify/cancel), 1.2초 큐·암호화 토큰 캐시 내장
- **실전 주문 안전장치(게이트 전 단계)**: confirmed 플래그 필수·guard 한도·화이트리스트·STOP·하루 손실을 관문에서 강제([[TSK-005]] 완성 후 게이트 경유로 전환)
- **Aside용 얇은 kis_client.js**: 함수 모양 동일(`make('real'|'mock')` → `price/balance/fills/order`), 내부만 관문 HTTP 호출로 교체, 관문 꺼짐 시 '[정지] 관문 꺼짐' 명확 오류
- **기동 명령**(실행 스크립트) + 기동 확인 방법 문서화
- **작업 스케줄러 등록/해제 스크립트**('로그온 시 시작', 현재 사용자 권한) — **실행은 군주가 직접 1회**(장수는 스크립트 작성만, 실행하지 않음 — [[ARC-009]] 확정)
- 로그·응답에 키·토큰 값 미기록(마스킹)

## 수용 조건 (AC)

1. 얇은 클라이언트로 모의 시세·잔고가 기존과 동일 형태로 반환된다(함수 모양 호환).
2. 토큰 없음/불일치 요청은 401, 외부 주소·잘못된 Host는 거부된다.
3. confirmed 없는 실전 주문이 관문에서 차단된다(전송 0건).
4. 관문 중단 상태에서 클라이언트가 '[정지] 관문 꺼짐' 오류를 반환하고 주문을 시도하지 않는다.
5. 디스크·로그·응답 어디에도 평문 키·KIS 토큰이 없다.
