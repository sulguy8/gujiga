## 상세 구현 범위

산출물:
- **데몬 조립**: 정시 엔진이 실제 시각표로 구동 — 08:30 시장 스냅샷([[TSK-015]]·[[TSK-016]]) → 08:31 군의(`gunshi.morningCouncil`, [[TSK-014]]) → 장중 5분 척후(scout → [액션 필요] 시 advise/insight 연결) → 15:05 전황 점검([[TSK-008]])
- **그림자 모드**: 이관 전까지 실전·모의 **주문 함수 호출 금지**(코드 레벨 차단 — 주문 경로 미연결). 산출물은 `gujiga-data/briefings` 등 **자체 폴더에만** 기록(Aside 산출물과 경로 분리 — RISK-004 중복 0). 알림은 PC OS 알림만(텔레그램은 봇 토큰 등록 후 활성화)
- **대조 기록**: 매 거래일 1행 — 날짜, 날씨·신호등·판정의 Aside 보고와의 일치 여부, 불일치 시 사유. 10거래일 누적 리포트(이관 조건 판정용). 사유 기록 예: 2026-11-27 앱 0/6 vs Aside 2/6 — 원인은 운영 상태 수동 입력 공백과 VIX 휴장 null의 보수 처리(판정 로직 결함 아님).
- **shadow.syncSignal1FromAside — 그림자 기간 한시(2026-11-27 군주 상책)**: 군의 직전에 Aside `reports/<date>.json`의 `signals_on`에서 신호1(악재 둔화)을 **읽기 전용**으로 가져와 `signal_inputs`를 갱신한다 — Aside 원본 쓰기 0건, 당일 파일 없으면 기존 값 유지, 출처는 `signal1_source`에 기록([[REQ-021]]). 이관 후에는 수동/자동 판정으로 전환 예정.
- **운영 상태 1회 시드(완료 2026-11-27)**: `signal_inputs`(신호1·event_within_2d)·`reentry_record`(SOX 기준 저점 8408.59/2026-11-20·recent3)·`event_calendar`(12-11 편입·동시만기)를 Aside 장부 값으로 시드(읽기 전용 — [[DAT-013]] '운영 상태 입력').
- **sox_recent3_low 갱신 루틴**: SOX 최근 3거래일 저점을 스냅샷 갱신 시 함께 유지(신호등 3번 입력)
- **VIX 휴장 유지**: 당일 overnight VIX가 null이면 직전 거래일 캐시에서 VIX만 이어 쓰기(최대 3거래일, 초과 시 보수 꺼짐 — 규칙 정본은 [[REQ-021]]·표기는 [[DAT-013]] `sources.vix='carried(<날짜>)'`).
- **상주 실행**: [[ARC-009]]와 같은 방식 — 작업 스케줄러 '로그온 시 시작' 등록 스크립트 작성(등록 실행은 군주)

## 수용 조건 (AC)

1. 그림자 모드에서 주문 함수 호출이 구조적으로 불가능하다(호출 경로 부재 — [[TST-017]]로 증명).
2. 거래일에 08:31 군의·5분 척후·15:05 점검이 캘린더대로 실행되고 산출물이 자체 폴더에 생성된다.
3. 대조 기록이 매 거래일 생성되고, 불일치 시 사유가 적힌다.
4. **이관 조건: 10거래일 대조에서 불일치 0건이거나 전 건 사유 설명 가능** — 충족 시 군주 확인 후 [[ARC-004]] 이관 개시.
5. LLM 호출이 하루 상한 8회([[ARC-007]] 확정)를 넘지 않는다.
6. 신호1 동기화는 Aside 보고 파일을 읽기만 한다(원본 변경 0건) — 당일 파일 부재 시 기존 값 유지, 동기화 시 `signal1_source` 기록.
