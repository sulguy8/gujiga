## 사전 환경 조건

**한 줄 요약: 책사단 엔진이 형식·재현성·호출 상한·폴백을 지키는지 가짜 AI 응답(fixture)으로 검사한다.**

- Node 내장 테스트만(zero-dependency). AI는 호출하지 않고 **스텁**(미리 준비한 JSON 응답)으로 대체. 실계좌·관문 호출 없음.

## 검증 시나리오 (Pass/Fail)

1. 정상 안건 → 의견 7건+종합 1건 append, 전부 형식 검증 통과 (Pass: 8 레코드·형식 OK).
2. 규칙 책사 재현성: 같은 입력 2회 → 곽가·법정·가후 의견 동일 (Pass: 완전 일치).
3. AI 스텁 호출 횟수 기록 → 안건 1건 처리에 최대 1회 (Pass: callCount<=1 — 호출 통합 방식이라 기존 군의·척후 호출에 편승하면 추가 호출 0회도 정상).
4. AI 스텁이 깨진 JSON 반환 → 4인 폴백(관망·확신 1·fallback) 기록, 예외 전파 없음.
5. 하루 상한 카운터 소진 상태 → AI 미호출(callCount 0)·4인 폴백.
6. 가중 다수결: 군사중랑장 출병 1 vs 종사 관망 2 → 종합 출병. 동률 → 보수 쪽.
7. 폴백 의견 가중 0: 폴백 4인 출병이어도 규칙 3인 쪽 결론 유지.
8. 가후 의견이 종합 출력에 항상 포함된다.
9. 주문 모듈 import·실행 플래그 접근이 없음(정적 검사).
10. 복수 아침 안건 동시 처리 → 군의 호출 1회를 공유 (Pass: 안건 수와 무관하게 callCount<=1).
