## 상위 근거

**TSK-030 — 그림자 08:30 계좌 스냅샷 실연결(관문 잔고 조회)**

**한 줄 요약: 거래일 08:30 계좌 스냅샷(총평가·현금)이 자동으로, 하루 1행씩, 실서버 호출 없이 안전하게 기록되는지 검증한다.**

## 사전 환경 조건

- **검증 대상**: [[TSK-030]] shadow.runSnapshot 비동기 허용 + run-shadow의 accountSnapshot 실연결.
- 사전 조건: 가짜 KIS(실서버 호출 없이 잔고 조회 응답을 흉내내는 테스트용 모듈)로 real·paper 잔고 응답을 주입. 임시 데이터 폴더(daily_account_snapshot 원장 초기화).
- **실행 방법: 자동(테스트 코드)** — 실서버 호출 0건. 테스트 코드 먼저 작성(실패 확인) 후 구현.

## 검증 시나리오 (Pass/Fail)

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 비동기 공급자(가짜 잔고 응답)로 runSnapshot 실행 | real·paper 스냅샷 각 1행 기록, 각 행에 총평가(start_total_eval)·현금(start_cash) 포함 |
| 2 | 1번 직후 같은 날 재실행 | 추가 기록 0건(멱등 — 일·계좌별 1행 유지) |
| 3 | 공급자가 실패(에러 throw 또는 거부)하는 상태로 실행 | 기록 생략, 데몬(틱 루프) 생존 — 예외가 밖으로 새지 않음. 다음 틱 재시도 가능 상태 |
| 4 | 기존 동기(즉시 반환) 공급자로 실행 | 종전과 동일하게 기록(하위 호환) — 기존 테스트 전부 통과 |
| 5 | 전 시나리오 통틀어 가짜 KIS의 호출 기록 검사 | 실서버 호출 0건, 잔고 '조회' 외의 호출(주문 등) 0건 |

## 경계값/에지 케이스

- 한쪽(real)만 실패하고 다른 쪽(paper)은 성공하는 날: 성공한 계좌만 1행 기록, 실패한 계좌는 생략(다음 틱 재시도).
- 날짜가 바뀐 뒤 실행: 새 날짜로 다시 각 1행 기록(멱등 키는 일·계좌 조합).
- 비동기 공급자가 영영 응답하지 않는 경우는 범위 밖(기존 틱 구조가 다루는 문제) — 테스트하지 않음을 명기.
